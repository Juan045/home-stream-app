Resumen del proyecto

Stream Media es un servicio de streaming de contenido multimedia auto-hospedado, inspirado en plataformas como Jellyfin. El sistema resuelve un problema concreto: dado un archivo de video almacenado en disco, permitir su reproducción inmediata desde cualquier navegador en la red local, con la posibilidad de elegir entre las pistas de audio y subtítulos disponibles en el archivo.

El flujo comienza cuando el usuario proporciona la ruta de un archivo — por ejemplo /home/peliculas/peli.mkv. El sistema analiza el archivo usando ffprobe para detectar el codec de video, las pistas de audio disponibles (con sus idiomas y codecs) y las pistas de subtítulos. Con esta información, determina la estrategia óptima: remux sin re-codificación (para H.264) o transcodificación a H.264 (para H.265 u otros codecs). El procesamiento inicia inmediatamente con la primera pista de audio y sin subtítulos.

El contenido se entrega al navegador como HLS en todos los casos, lo que permite un pipeline uniforme. El usuario puede cambiar la pista de audio o activar subtítulos en cualquier momento durante la reproducción, y puede navegar libremente por la línea de tiempo sin esperar a que se procese el video completo — el sistema codifica desde el punto solicitado.

Esta primera iteración se centra en el motor de procesamiento, entrega y selección de pistas. No incluye biblioteca de medios, autenticación ni interfaz de gestión — es el núcleo funcional sobre el que se construirá todo lo demás.

Alcance del MVP

Incluido

  • Recibir ruta de archivo local como entrada
  • Detección automática de codec, contenedor, pistas de audio y subtítulos con ffprobe
  • Remux para H.264 en cualquier contenedor (sin re-codificación de video)
  • Transcodificación H.264 + AAC para H.265 y otros codecs
  • Entrega HLS para todos los casos
  • Selección de pista de audio por el usuario
  • Subtítulos de texto (SRT, ASS) extraídos a WebVTT
  • Seek libre — codificación desde cualquier punto de la línea de tiempo
  • Reproductor web integrado con hls.js
  • Gestión automática de archivos temporales
  • Progreso de procesamiento en tiempo real
  • API REST para gestionar operaciones

Futuro

  • Adaptive Bitrate Streaming (ABR)
  • Codec AV1
  • Subtítulos de imagen (PGS, VOBSUB)
  • Encoding por hardware (NVENC, VA-API, AMF)
  • Autenticación y control de acceso
  • Biblioteca y escaneo de medios
  • Segmentos fMP4 (.m4s) como alternativa a .ts
Formatos soportados: .mp4 y .mkv como contenedores principales. Codecs de entrada: H.264 y H.265. Subtítulos de texto: SRT y ASS/SSA (convertidos a WebVTT). Otros contenedores (.avi, .mov, .webm), codecs y subtítulos de imagen se consideran futuros.

Requerimientos

Funcionales

RF-01 Recibir una ruta absoluta de archivo de video como entrada a través de la API REST.
RF-02 Validar que el archivo existe en disco y que su extensión es soportada (.mp4, .mkv).
RF-03 Analizar el archivo con ffprobe para detectar el codec de video, todas las pistas de audio (codec, idioma, canales) y todas las pistas de subtítulos (formato, idioma).
RF-04 Determinar automáticamente la estrategia de procesamiento basada en el codec de video: remux (H.264) o transcodificación (H.265 u otros).
RF-05 Remuxear archivos H.264 (cualquier contenedor) sin re-codificación de video, mapeando la pista de audio seleccionada y generando segmentos HLS (.ts) y manifest (.m3u8).
RF-06 Transcodificar archivos H.265 (u otros codecs no soportados) a H.264 + AAC, mapeando la pista de audio seleccionada y generando segmentos HLS.
RF-07 Iniciar el procesamiento automáticamente con la primera pista de audio disponible y sin subtítulos.
RF-08 Proveer al usuario la lista de pistas de audio y subtítulos disponibles en el archivo.
RF-09 Permitir al usuario cambiar la pista de audio durante la reproducción. El sistema detiene el proceso FFmpeg actual y reinicia con la pista seleccionada.
RF-10 Permitir al usuario activar, cambiar o desactivar subtítulos durante la reproducción. Los subtítulos de texto (SRT, ASS) se extraen a WebVTT bajo demanda, sin reiniciar FFmpeg.
RF-11 Permitir seek libre: el usuario puede navegar a cualquier punto de la línea de tiempo. El sistema detiene FFmpeg y reinicia la codificación desde el timestamp solicitado usando -ss.
RF-12 Servir los segmentos HLS y el manifest a través de HTTP en un puerto configurable.
RF-13 Proveer un reproductor web embebido que reproduzca el contenido usando hls.js, con controles para selección de pista de audio y subtítulos.
RF-14 Reportar el progreso de procesamiento como porcentaje, consultable vía API.
RF-15 Permitir consultar el estado de todos los jobs (pendiente, procesando, listo, fallido).
RF-16 Permitir iniciar la reproducción antes de que el procesamiento termine — los primeros segmentos HLS se sirven mientras FFmpeg genera los restantes.
RF-17 Eliminar automáticamente los archivos temporales (segmentos HLS, subtítulos) cuando la sesión de visualización termina.
RF-18 Limitar el número de procesos FFmpeg concurrentes a un máximo configurable (por defecto: 2).

No funcionales

RNF-01 Para remux, el primer segmento HLS debe estar disponible en menos de 5 segundos.
RNF-02 La extracción de un subtítulo de texto a WebVTT debe completarse en menos de 2 segundos.
RNF-03 El sistema debe soportar al menos 5 streams simultáneos de reproducción.
RNF-04 Los segmentos HLS deben tener una duración de 6 segundos, alineada con la recomendación de Apple.
RNF-05 El servicio debe funcionar en Linux y Windows sin modificaciones al código.
RNF-06 Logs estructurados (JSON) con niveles de severidad para facilitar monitoreo y debugging.
RNF-07 El espacio en disco temporal no debe exceder un límite configurable (MAX_TEMP_STORAGE, por defecto: 50 GB).
RNF-08 Tras un seek o cambio de pista de audio, el primer segmento debe estar disponible en menos de 5 segundos para remux y menos de 15 segundos para transcodificación.

Arquitectura del sistema

El sistema se compone de cinco elementos principales: el archivo de video como entrada, un analizador que detecta codec, pistas de audio y subtítulos mediante ffprobe, un router que selecciona la estrategia de procesamiento (remux o transcodificación), un worker de FFmpeg que ejecuta el procesamiento, y un servidor FastAPI que orquesta todo el proceso y sirve el contenido al navegador.

Diagrama de componentes

El Servidor FastAPI es el componente central. Cumple cinco funciones: expone la API REST para recibir solicitudes, invoca al analizador para determinar la estrategia y las pistas disponibles, orquesta los procesos de FFmpeg para remux o transcodificación, gestiona la selección de pistas de audio y subtítulos por parte del usuario, y sirve el contenido al navegador como segmentos HLS y archivos WebVTT.

El Analizador usa ffprobe para inspeccionar el archivo de video y extraer toda la información de sus streams: codec de video, cada pista de audio (con codec, idioma, número de canales y título) y cada pista de subtítulos (con formato e idioma). Con esta información, determina la estrategia de procesamiento y provee las opciones disponibles al usuario.

El Sesión Manager controla el ciclo de vida de los archivos temporales y las operaciones de seek. Monitorea la actividad del cliente mediante heartbeats, gestiona los reinicios de FFmpeg cuando el usuario cambia de pista de audio o hace seek, y aplica un TTL de inactividad para eliminar los archivos cuando ya no se necesitan.

POST /api/v1/jobs/{job_id}/select

Cambia la pista de audio activa y/o activa/desactiva subtítulos. Ambos campos son opcionales — se envía solo lo que cambia. El comportamiento depende de qué se modifica:

Cambio de audio: detiene el proceso FFmpeg actual y reinicia con la nueva pista mapeada (-map 0:a:{index}), manteniendo la posición actual de reproducción. La reproducción se interrumpe brevemente.

Cambio de subtítulo: extrae la pista seleccionada a WebVTT (operación instantánea). No reinicia FFmpeg — la reproducción continúa sin interrupción. Enviar null desactiva los subtítulos.

GET /stream/{job_id}/master.m3u8

Sirve el manifest HLS. Content-Type: application/vnd.apple.mpegurl. El manifest se actualiza a medida que se generan nuevos segmentos y se reconstruye tras un seek o cambio de pista de audio.

Sirve un segmento individual de video. Content-Type: video/mp2t. Los segmentos se numeran secuencialmente desde 000. Tras un seek, la numeración se ajusta con -start_number para mantener coherencia con la posición temporal.

Sirve un archivo de subtítulos WebVTT extraído bajo demanda. Content-Type: text/vtt. El archivo se genera cuando el usuario selecciona la pista de subtítulos y se cachea en disco para solicitudes subsiguientes. El nombre sigue el formato sub_{index}_{language}.vtt.

Sirve una página HTML con el reproductor configurado para el job indicado. Usa hls.js para reproducir el contenido HLS. Incluye controles para selección de pista de audio y subtítulos (con las opciones reportadas por la API), lógica de heartbeat automático, y manejo de seek que invoca al endpoint correspondiente.

Pipeline de procesamiento

El sistema implementa dos niveles de procesamiento, seleccionados automáticamente según el codec de video del archivo de entrada. En ambos casos, la salida es HLS, lo que permite un pipeline uniforme para selección de pistas, subtítulos y seek.

Detección de codec y pistas

Al recibir una solicitud, el analizador ejecuta ffprobe para inspeccionar todos los streams del archivo:

ffprobe -v quiet -print_format json \
  -show_streams -show_format \
  /ruta/al/video.mkv

Del resultado se extraen: codec_name del stream de video, y para cada stream de audio y subtítulos su codec, idioma (tags.language), título, y número de canales (para audio). La lógica de decisión es:

# Lógica de detección (pseudocódigo)
async def analyze_file(path: str) -> AnalysisResult:
    probe = await run_ffprobe(path)
    video_codec = get_video_codec(probe)
    audio_tracks = get_audio_tracks(probe)      # [{index, lang, codec, channels, title}]
    subtitle_tracks = get_subtitle_tracks(probe) # [{index, lang, format, title}]

    if video_codec == "h264":
        strategy = StreamStrategy.REMUX
    else:
        strategy = StreamStrategy.TRANSCODE

    return AnalysisResult(
        strategy=strategy,
        video_codec=video_codec,
        audio_tracks=audio_tracks,
        subtitle_tracks=subtitle_tracks,
        duration=get_duration(probe)
    )

Niveles de procesamiento

NIVEL 1 Remux

Condición: Video H.264 en cualquier contenedor (MP4, MKV, u otro).

Acción: Reempaquetado en segmentos HLS sin re-codificación de video (-c:v copy). Solo la pista de audio seleccionada se mapea al output. Si el codec de audio no es compatible con HLS (e.g. flac, opus, dts), se transcodifica solo el audio a AAC; si ya es AAC, se copia sin re-codificar.

Costo: CPU ≈ 5-10%. Velocidad ≈ 50-100x tiempo real. Disco temporal ≈ tamaño original del archivo.

ffmpeg -i /ruta/al/video.mkv \
  -map 0:v:0 \
  -map 0:a:0 \
  -c:v copy \
  -c:a aac -b:a 128k \
  -f hls \
  -hls_time 6 \
  -hls_list_size 0 \
  -hls_segment_filename 'output/{job_id}/segment_%03d.ts' \
  output/{job_id}/master.m3u8
Si el audio seleccionado ya es AAC, se usa -c:a copy en lugar de re-codificar. El analizador detecta el codec de cada pista y el transcoder decide automáticamente.
NIVEL 2 Transcodificación

Condición: Video H.265 (HEVC) u otro codec no soportado nativamente por la mayoría de navegadores.

Acción: Re-codificación del video a H.264 y audio a AAC (si no es ya AAC), mapeando solo la pista de audio seleccionada.

Costo: CPU ≈ 200-400%. Velocidad ≈ 0.3-1.5x tiempo real para 1080p. Disco temporal ≈ 30-50% del tamaño original. Memoria ≈ 200-500 MB por proceso FFmpeg.

ffmpeg -i /ruta/al/video.mkv \
  -map 0:v:0 \
  -map 0:a:0 \
  -c:v libx264 \
  -preset veryfast \
  -crf 23 \
  -c:a aac \
  -b:a 128k \
  -ac 2 \
  -f hls \
  -hls_time 6 \
  -hls_list_size 0 \
  -hls_segment_filename 'output/{job_id}/segment_%03d.ts' \
  -force_key_frames 'expr:gte(t,n_forced*6)' \
  output/{job_id}/master.m3u8
Se usa -preset veryfast para priorizar la velocidad de codificación. El preset es configurable vía FFMPEG_PRESET.

Selección de pistas de audio

Al iniciar un job, el sistema mapea automáticamente la primera pista de audio disponible (-map 0:a:0). Cuando el usuario selecciona una pista diferente a través del endpoint /select, el sistema:

# Pseudocódigo de cambio de pista de audio
async def change_audio_track(job: Job, audio_index: int):
    # 1. Guardar posición actual de reproducción
    current_position = job.current_playback_position

    # 2. Detener el proceso FFmpeg actual
    await kill_ffmpeg(job.ffmpeg_process)

    # 3. Determinar si el audio necesita re-codificación
    track = job.audio_tracks[audio_index]
    audio_codec = "copy" if track.codec == "aac" else "aac"

    # 4. Reiniciar FFmpeg con la nueva pista desde la posición actual
    job.ffmpeg_process = await start_ffmpeg(
        input=job.file_path,
        seek=current_position,
        video_map="0:v:0",
        audio_map=f"0:a:{audio_index}",
        audio_codec=audio_codec,
        ...
    )
    job.current_audio_track = audio_index

El cambio de audio siempre implica reiniciar FFmpeg porque la pista mapeada cambia. La reproducción se retoma desde la posición actual usando -ss.

Extracción de subtítulos

Los subtítulos no se extraen al iniciar el job — se extraen bajo demanda cuando el usuario activa una pista. La extracción de subtítulos de texto (SRT, ASS/SSA) a WebVTT es una operación instantánea que no requiere reiniciar el proceso FFmpeg de video, por lo que la reproducción no se interrumpe.

# Extracción de subtítulo a WebVTT
ffmpeg -i /ruta/al/video.mkv \
  -map 0:s:0 \
  -c:s webvtt \
  output/{job_id}/subtitles/sub_0_spa.vtt

Una vez extraído, el archivo .vtt se cachea en disco — si el usuario desactiva y vuelve a activar la misma pista, no se vuelve a extraer. El reproductor carga el subtítulo como un <track> en el elemento <video>.

Los subtítulos de imagen (PGS, VOBSUB) no están soportados en el MVP. Requieren OCR para convertirlos a texto, o quemarlos en el video (-filter_complex overlay), lo cual implica re-codificación. Se consideran para una iteración futura.

Seek libre

El usuario puede navegar a cualquier punto de la línea de tiempo sin esperar a que el video se procese secuencialmente. Al recibir una solicitud de seek, el sistema detiene el proceso FFmpeg actual y lo reinicia desde el timestamp solicitado:

# Seek a minuto 45 (2700 segundos)
ffmpeg -ss 2700 -i /ruta/al/video.mkv \
  -map 0:v:0 \
  -map 0:a:0 \
  -c:v copy \
  -c:a aac -b:a 128k \
  -f hls \
  -hls_time 6 \
  -hls_list_size 0 \
  -start_number 450 \
  -hls_segment_filename 'output/{job_id}/segment_%03d.ts' \
  output/{job_id}/master.m3u8

El flag -ss antes de -i hace input seeking: FFmpeg salta directamente al keyframe más cercano sin decodificar todo lo anterior. Esto es casi instantáneo para remux y tarda pocos segundos para transcodificación. El -start_number 450 (calculado como timestamp / hls_time) mantiene la numeración de segmentos coherente con la posición temporal.

Los segmentos generados previamente se conservan en disco. Si el usuario salta hacia adelante y luego vuelve atrás a una posición ya procesada, el servidor sirve los segmentos existentes sin reiniciar FFmpeg.

El seek preserva la selección actual de pista de audio — el reinicio de FFmpeg usa el mismo -map de audio que estaba activo. Los subtítulos extraídos (archivos .vtt) no necesitan regenerarse porque cubren todo el archivo.

Parámetros clave de FFmpeg

-map 0:v:0 / -map 0:a:{n}
Selecciona explícitamente qué streams del archivo de entrada incluir en la salida. 0:v:0 es el primer stream de video, 0:a:{n} es la enésima pista de audio. Solo se mapea la pista de audio seleccionada por el usuario.
-c:v copy
Copia el stream de video sin re-codificar. Se usa en Nivel 1 (remux). No consume CPU significativa.
-c:v libx264
Codec de video H.264. Solo se usa en Nivel 2 (transcodificación). Soportado nativamente por todos los navegadores.
-crf 23
Constant Rate Factor. Controla la calidad visual en una escala de 0 a 51. 23 es el valor por defecto de libx264 y ofrece un buen balance entre calidad y tamaño.
-c:a aac -b:a 128k
Audio AAC a 128 kbps. Compatible universalmente con HLS. Se usa -c:a copy cuando el audio de origen ya es AAC.
-c:s webvtt
Convierte subtítulos de texto (SRT, ASS/SSA) al formato WebVTT, que es el estándar para subtítulos en navegadores.
-ss {timestamp} (antes de -i)
Input seeking. Salta directamente al keyframe más cercano al timestamp indicado sin decodificar los frames anteriores. Es la base del seek libre.
-start_number {n}
Número inicial para la secuencia de segmentos HLS. Se calcula como timestamp / hls_time para mantener la numeración alineada con la línea de tiempo del video tras un seek.
-hls_time 6
Duración objetivo de cada segmento en segundos. 6 segundos es la recomendación de Apple.
-hls_list_size 0
Mantiene todos los segmentos en el playlist (modo VOD).
-force_key_frames 'expr:gte(t,n_forced*6)'
Fuerza un keyframe cada 6 segundos en transcodificación, alineado con la duración de los segmentos.

Monitoreo de progreso

FFmpeg reporta su progreso por stderr. El servicio parsea la salida buscando el campo time=, que indica el timestamp del último frame procesado. Comparándolo con la duración total (obtenida con ffprobe), se calcula el porcentaje de avance. Cuando hay un seek activo, el progreso se calcula relativo al rango que se está procesando.

# Salida típica de FFmpeg (stderr):
frame= 1234 fps=45 q=29.0 size=12345kB time=00:05:23.45 bitrate=312.5kbits/s speed=1.8x

# El servicio extrae time=00:05:23.45 y calcula:
# progreso = (323.45 / duracion_total) * 100

Seguridad

La ruta de archivo proporcionada por el usuario es un vector de ataque potencial. El servicio debe validar que la ruta es absoluta, que no contiene secuencias de path traversal (../), que el archivo existe físicamente, y opcionalmente que está dentro de un directorio base configurable (MEDIA_ROOT). Nunca se debe pasar la ruta directamente al shell sin sanitizar.

Gestión de almacenamiento

Todos los jobs generan archivos temporales: segmentos HLS (.ts), manifests (.m3u8) y opcionalmente subtítulos extraídos (.vtt). El sistema implementa un ciclo de vida de sesión con tres mecanismos de limpieza para evitar la acumulación.

Ciclo de vida de sesión

Cada job tiene una sesión asociada con el siguiente ciclo:

Mecanismo 1: Heartbeat + TTL

El reproductor web envía un heartbeat (POST /api/v1/heartbeat/{job_id}) cada 30 segundos. Si no se recibe heartbeat durante 2 minutos, la sesión se marca como inactiva. Tras 10 minutos adicionales sin actividad (TTL), todos los archivos temporales del job se eliminan automáticamente — incluyendo segmentos HLS y subtítulos extraídos.

Los intervalos son configurables: HEARTBEAT_INTERVAL=30, INACTIVE_THRESHOLD=120, SESSION_TTL=600.

Mecanismo 2: Limpieza al inicio

Al arrancar el servidor, el sistema escanea el directorio output/ y elimina todos los subdirectorios de sesiones anteriores. El directorio output/ se considera efímero.

# Pseudocódigo de startup cleanup
async def startup_cleanup():
    output_dir = Path(settings.OUTPUT_DIR)
    if output_dir.exists():
        for job_dir in output_dir.iterdir():
            if job_dir.is_dir():
                shutil.rmtree(job_dir)
                log.info("startup_cleanup", job_id=job_dir.name)

Mecanismo 3: Límite de almacenamiento

El sistema mantiene un contador del espacio total ocupado por archivos temporales. Antes de iniciar un nuevo job, verifica que el espacio proyectado no exceda MAX_TEMP_STORAGE. Si lo excede, retorna un error 507 Insufficient Storage.

En el MVP, el estado de los jobs se mantiene en memoria (un diccionario Python). Esto incluye la selección actual de pista de audio y subtítulo, y la referencia al proceso FFmpeg activo (para poder detenerlo en seek y cambio de pista). Al reiniciar el servidor se pierde el historial de jobs — consistente con la política de que output/ se limpia al inicio.

Configuración

Todas las opciones se configuran vía variables de entorno, con valores por defecto sensatos:

# Servidor
HOST=0.0.0.0
PORT=8000

# Rutas
MEDIA_ROOT=/home/peliculas        # Directorio base permitido (opcional)
OUTPUT_DIR=./output               # Directorio para archivos temporales

# FFmpeg
FFMPEG_PRESET=veryfast            # Preset de libx264 para transcodificación
FFMPEG_CRF=23                     # Calidad de transcodificación
MAX_CONCURRENT_FFMPEG=2           # Máximo de procesos FFmpeg simultáneos

# Sesión y limpieza
HEARTBEAT_INTERVAL=30             # Segundos entre heartbeats del cliente
INACTIVE_THRESHOLD=120            # Segundos sin heartbeat para marcar inactiva
SESSION_TTL=600                   # Segundos de inactividad antes de eliminar
MAX_TEMP_STORAGE=53687091200      # 50 GB en bytes

FFmpeg y ffprobe son dependencias del sistema — deben estar instalados y accesibles en el PATH. No se usa una librería wrapper de Python para FFmpeg; la invocación directa via asyncio.create_subprocess_exec da control total sobre los argumentos, el manejo de la salida, y la capacidad de detener el proceso para seek y cambio de pistas.
